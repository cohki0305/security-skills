# 指示書: Mac の実機でセキュリティ診断スキルを確かめる

Mac で動く Claude Code に渡す指示書です。読み手は、このリポジトリについて何も知らない前提で書いています。

## 背景

このリポジトリの `security-checkup/` は、中小企業向けのセキュリティ診断スキルです。PC の設定を同梱の読み取り専用スクリプトで読み、質問への回答と合わせて「事故の場面ごと」のレポートをブラウザに出します。Mac 版のスクリプトは `security-checkup/checks/mac/run.sh`（bash 3.2 で動く書き方）です。

開発は Linux と Windows で行い、Mac の部分はコマンドの出力をまねた偽物（`tests/mac-shims`）でしかテストしていません。そこで、本物の Mac で次の 2 つを確かめます。

1. スクリプトが読む値が、Mac の実際の設定と合っているか
2. スキルとして Claude Code から使ったとき、確認画面なしで最後まで進むか

この作業で見つけるのは問題点です。直すのは別の担当者です。

- 作業場所: `~/security-skills`（main ブランチ）
- 現状: Linux 上で `bun test` が 216 件すべて通っている
- 作業量の目安: 30〜40 分（そのうち利用者に設定画面を見てもらう時間が半分ほど）

## 作業ルール

1. **Mac の設定を変えない。** `sudo` を使わない。管理者のパスワードを求められたら、入力せずに止めて利用者に知らせる。
2. **コードを直さない。push しない。** 問題を見つけたら記録だけする。
3. 実行するのは、手順書 `docs/mac-test-checklist.md` に書かれたコマンドと、この指示書に書いたコマンドだけ。
4. Claude からは「システム設定」の画面が見えない。実際の設定は利用者に見てもらい、答えを聞く。1 回に聞くのは 2〜3 項目までにする。
5. 報告には、Mac のユーザー名、Mac の名前、ホームフォルダのパスを書かない。出てきたら `〔ユーザー名〕` `〔Mac の名前〕` に置き換える。
6. 利用者への説明は日本語で、専門用語を避けて書く。

---

## Task 1【必須】リポジトリが置けていることを確かめる

`~/security-skills` にこのリポジトリがあり、main の最新になっていることを確かめる。

```
git -C ~/security-skills status
git -C ~/security-skills log --oneline -1
```

macOS のバージョンと、利用者のアカウントが管理者かどうかを控える。

```
sw_vers
id -Gn
```

`id -Gn` に `admin` があれば管理者。

**検証**: macOS のバージョンと、管理者かどうかが報告に書けること。

## Task 2【必須】手順書の部品テストを通す

`docs/mac-test-checklist.md` を読み、「準備」から「5. 日本語と空白が入った保存先でも動くか」まで順に進める。コマンドはリポジトリのフォルダで実行する。

手順 3 の表は、1 行ずつ次のように進める。

1. `mac-result.json` の値を、利用者向けの言葉で伝える（例:「FileVault がオンと出ています」）
2. 「システム設定」の該当画面を見てもらい、合っているか聞く
3. 合っている／違う／わからない、を記録する

手順書にない点で、特に確かめたいことが 3 つある。

- **管理者でないときの動き**: 利用者が管理者なら、この点は「未確認（管理者で実行）」と書くだけでよい。標準ユーザーなら、`local_admin` と `remote_access` の値と `unavailable` を記録する。中の `sysadminctl` と `launchctl` が、管理者でないと答えを返さないことがあるため。
- **macOS の許可の確認画面**: 手順 2 の実行中に、「"ターミナル"が"書類"フォルダ内のファイルへのアクセスを求めています」のような画面が出たか、利用者に聞く。出たなら、どのフォルダについてかを記録する。クラウド同期（`cloud_sync`）が `~/Library/CloudStorage` などを見るため。
- **XProtect の更新日（macOS 15 以降）**: `antivirus` の `definitionsUpdatedAt` と、次の 2 つの日付を並べて記録する。

  ```
  stat -f %Sm /Library/Apple/System/Library/CoreServices/XProtect.bundle/Contents/Info.plist
  system_profiler SPInstallHistoryDataType
  ```

  2 つ目は出力が長い。XProtect を含む項目のうち、いちばん新しい日付だけを拾う。

**検証**: 手順 1〜5 それぞれに合格／不合格が付き、手順 3 の 11 項目それぞれに「合っている／違う／わからない」が付いていること。

## Task 3【必須】スキルとして最後まで使ってみる

スキルの許可の設定（`security-checkup/SKILL.md` の `allowed-tools`）が Mac で効くかを確かめる。ここは利用者に手を動かしてもらう。

1. `docs/mac-install-latest.md` の Task 3 のとおりにスキルを置く。古い版があれば、上書きせずにゴミ箱へ移してから置く（上書きすると、古い版にだけあったファイルが残る）。
2. `diff -r ~/security-skills/security-checkup ~/.claude/skills/security-checkup` で何も出ないことを確かめる。

3. 利用者に、**新しいターミナルで新しい Claude Code を起動して**、次の 2 つを試してもらう。今のセッションにはスキルが読み込まれていないため、新しいセッションが要る。
   - 「PC の診断をしたい」と話しかけ、一般社員として最後まで答える
   - 続けて「会社のセキュリティ診断をしたい」と話しかけ、総務・情シス担当として最後まで答える（質問は適当に答えてよい。PC の台数も適当でよい）
4. 試している間に、次の点を見ておいてもらう。終わったら、このセッションに戻って結果を教えてもらう。
   - `run.sh` を実行するときに、許可の確認画面が出たか。出たなら、何回出て、どのコマンドだったか。**出ないのが期待どおり**
   - レポートがブラウザで開いたか。3 つの画面（レポート、業者・担当者に聞くこと、PC ごとの結果）が見られたか
   - 会社の診断の「PC ごとの結果」に、先に診断した自分の PC が出たか
   - チャットで、全体のレベル（A〜E）や場面ごとの良し悪しを Claude が言っていないか。**言わないのが期待どおり**
   - 文字化け、表示の崩れ、わかりにくい質問がなかったか

**検証**: 上の 5 点すべてに答えが記録されていること。

## Task 4【必須】報告をまとめる

結果を `~/Desktop/mac-test-report.md` に書く。形は次のとおり。

```markdown
# Mac 実機確認の結果

- 日付:
- macOS:
- 管理者か:

## 部品テスト（手順書 1〜5）
| 手順 | 結果 | メモ |

## 11 項目の値と実際の設定
| 項目 | スクリプトの値 | 実際の設定 | 合っているか |

## 特に確かめた 3 点
- 管理者でないときの動き:
- macOS の許可の確認画面:
- XProtect の更新日: スクリプトの値 / Info.plist の日付 / インストール履歴の日付

## スキルとして使った結果
- 許可の確認画面:
- レポートの表示:
- 自分の PC が会社のレポートに出たか:
- チャットでレベルを言ったか:
- 気になった点:

## 見つかった問題
（再現の手順と、実際に出た表示。値が合わなかった項目は、そのときのコマンドの出力の該当部分）
```

ユーザー名などを置き換えたことを確かめてから、利用者に報告のファイルの場所を伝える。

利用者が `gh` でログインしているなら、この報告を GitHub の issue にしてよいか聞く。よいと言われたら次を実行する。

```
gh issue create -R "$(git -C ~/security-skills remote get-url origin)" --title "Mac 実機確認の結果" --body-file ~/Desktop/mac-test-report.md
```

**検証**: 報告のファイルがあり、ユーザー名・Mac の名前・ホームフォルダのパスが入っていないこと。

```
grep -n "$(whoami)\|$(scutil --get ComputerName 2>/dev/null)\|/Users/" ~/Desktop/mac-test-report.md
```

何も出なければよい。

## Task 5【任意】後片付け

Task 4 のあとで、利用者に聞いてから行う。

- `~/Documents/セキュリティ診断/試し` フォルダを消す
- `~/.claude/skills/security-checkup` を残すか消すかは利用者が決める

## スコープ外（この作業ではやらない）

- コードや手順書の修正、コミット、push: 直す担当者は別にいる。ここで直すと、何が Mac で起きたのかが追えなくなる
- Windows での確認: 別の機会に行う
- テスト（`bun test`）の実行: Linux で通っている。Mac に bun を入れる必要はない
- 診断の結果に従って Mac の設定を変えること: このスキルは読むだけの道具。変えるかどうかは利用者が別に決める

## 完了条件

- Task 1〜4 が終わり、`~/Desktop/mac-test-report.md` がある
- 報告に、見つかった問題が再現の手順付きで書かれている（なければ「なし」と書く）
- Mac の設定は何も変わっていない
